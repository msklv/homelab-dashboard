# homelab-dashboard — спецификация устройства

Нативное macOS-приложение (Apple Silicon/ARM), дашборд мониторинга Linux/macOS-серверов по SSH.
Отображает живое состояние хостов: статус, паспорт (cores/RAM/диск тип+объём/uptime/температура),
нагрузку (CPU/RAM/сеть/диск I-O), разбивку на группы, цветные теги, светлый/тёмный режим.
Конфигурация — YAML, изменения применяются мгновенно (hot-reload) без перезапуска.

---

## 1. Цели и не-цели

**Цели**
- Мониторинг в реальном времени, без истории: только текущие живые значения.
- **Ноль внешних зависимостей:** собственный мини-YAML-парсер (`YamlMini`) вместо стороннего
  пакета; собственный self-contained test-runner (`Check`) вместо XCTest. Всё остальное — системные
  бинарники macOS (`/usr/bin/ssh`, `ping`, `top`, `df`, `vm_stat`, `iostat`, …) и SDK (SwiftUI, Foundation).
- Сборка/запуск строго под ARM (Apple Silicon), macOS 13+, SwiftPM-only (без Xcode-проекта).
- Авторизация на хостах переиспользует `~/.ssh/config`, `known_hosts` и ключи — пароли не хранятся.
- **Ничего не ставится и не запускается на серверах:** только чтение вывода стандартных команд
  по SSH (pull), без install/pip/apt/sudo/root. Команды, которых нет на хосте, дают `N/A`.

**Не-цели (осознанно исключено)**
- История метрик, спарклайны, графики за период.
- Уведомления при offline/warning («нет уведомлений, только подсветка в UI»).
- Управление хостами (deploy/exec/reboot) — кроме одного: кнопка терминала `›_` открывает `ssh` в Terminal.app.
- Агент на целевых серверах — только pull по SSH.

## 3. Архитектура

```
┌─────────────────────────────────────────────┐
│ SwiftUI (окно)                               │
│  SummaryCard(Итого/Онлайн/Оффлайн)          │
│  GroupSection / HostGrid, HostCard          │
│  TagFilter, ThemeToggle, кнопка терминала    │
└──────────────▲──────────────────────────────┘
        данные / ObservableObject (DashboardModel)
┌──────────────┴──────────────────────────────┐
│ Poller (Timer по poll_interval, параллелизм  │
│  max_concurrent; /usr/bin/ssh 'batch';       │
│  дельта-счётчики net/disk-I/O)               │
└──────────────▲──────────────────────────────┘
│ Config (YamlMini) ── DispatchSource FSEvents ── hot-reload
```

Поток односторонний: Config → Poller → DashboardModel → SwiftUI. Модель хранит последний
валидный snapshot хоста; после N пропусков хост уходит в offline, но прошлые метрики не стираются.

## 4. Схема YAML-конфига

```yaml
poll_interval: 5          # ОПЦИОНАЛЬНО, сек (по умолчанию 5)
timeout: 5                # сек, таймаут ssh-сессии
offline_after_misses: 2   # N неудачных опросов подряд → offline
max_concurrent: 4         # параллельных ssh
theme: system             # system | light | dark

thresholds:               # пороги окраски колец CPU/RAM (в %)
  warning: 60             #   зелёный → оранжевый
  critical: 85            #   оранжевый → красный

groups:                   # ОПЦИОНАЛЬНО: секции-заголовки
  - name: Кластер k8s
    collapsed: true       # ОПЦИОНАЛЬНО: стартовать свёрнутой (хосты не опрашиваются)
  - name: NAS / storage

tags:                     # ОПЦИОНАЛЬНО: цветные теги-фильтры
  - { name: prod, color: green }
  - { name: backup, color: blue }
  - { name: critical, color: red }

hosts:
  # Обязательны ТОЛЬКО name и ssh. ОС определяется автоматически (uname),
  # метрики собираются все; недоступные на конкретной ОС → N/A.
  - name: k8s-01           # идентификатор для merge при hot-reload
    ssh: root@192.0.2.10   # реальные доступы — в приватном config.yaml
    group: Кластер k8s     # ОПЦИОНАЛЬНО: секция-группа (нет — «Прочее»/плоско)
    tags: [prod, critical] # ОПЦИОНАЛЬНО: теги-фильтры
  - name: mac-mini
    ssh: user@192.0.2.12
    poll_interval: 10      # ОПЦИОНАЛЬНО: свой период обновления
    group: NAS / storage
    tags: [backup]
```

Правила:
- Все поля опциональны, кроме `name` + `ssh`.
- `os` **не указывается** — автодетект через `uname` при первом опросе. Поля `region`/`metrics` **не используются**.
- `name` — стабильный идентификатор; при hot-reload состояние хоста переиспользуется (дельта-счётчики не сбрасываются).
- `collapsed: true` у группы — стартовая/сохранённая свёрнутость. Свёрнутая группа не опрашивается (автопауза мониторинга); состояние персистится при сворачивании в UI. Хосты без группы принадлежат синтетической «Прочее» — её свёрнутость живёт только в рамках сессии (в YAML секции нет).
- Реальные IP/имена — только в приватном `config.yaml` (в `.gitignore`); в `config.example.yaml` — заглушки.

## 5. Метрики и команды сбора

Сбор — одной ssh-сессией пачкой команд (batch, вывод строгим `HL_KEY=value`); дельта-счётчики
(сеть/диск-I/O) = разница между последовательными опросами. Недоступная метрика → `N/A`.

| Метрика | Linux | macOS | Примечание |
|---|---|---|---|
| ОС / hostname | `uname -s` / `hostname` | `uname -s` / `hostname` | заголовок = системный hostname |
| CPU % | `top -bn1` `%Cpu` (100−idle) | `top -l 1` «CPU usage» | живое |
| Cores | `nproc` | `sysctl -n hw.ncpu` | статично |
| RAM total | `/proc/meminfo` MemTotal×1024 | `sysctl -n hw.memsize` | статично |
| RAM used % | `(MemTotal−MemAvailable)/MemTotal` | **(active+inactive+spec − file-backed) + wired + compressor** (по `vm_stat`) | как Activity Monitor: App+Wired+Compressed |
| Disk total | **корневой раздел** `df -B1 /` | **корневой раздел** `df -b 1 /` ×512 (APFS-контейнер) | десятичные GB |
| Disk kind | `lsblk -dbrno name,type,rota`, приоритет **nvme>ssd>hdd** | `diskutil info /` Protocol → nvme/ssd | бейдж типа диска |
| Uptime | `/proc/uptime` | `sysctl kern.boottime` | сек → «Xd Yh» |
| Температура | thermal zones (`x86_pkg_temp`/`cpu_thermal`/…) temp + board | **N/A** (нужен root/powermetrics) | на mac — прочерк |
| Аплинк | `speed` интерфейса **маршрута по умолчанию** (`/proc/net/route`, фильтр виртуальных) | max `*baseT` из `ifconfig -l` | бейдж 100/1G/2.5G/10G |
| Сеть ↑/↓ | `/proc/net/dev` rx/tx дельта | `netstat -ib` rx/tx дельта | `B/s`→`K/s` |
| Диск I/O R/W | `/proc/diskstats` (поле 3, sectors×512) дельта | `iostat -w 1 -c 2` (R; W → N/A) | `B/s` |

Ненулевой код выхода/таймаут ssh = неуспешный опрос; хост считает промахи → offline.

## 6. Спецификация UI

### 6.1 Сводные карточки
**Итого** (синяя точка + число из конфига) · **Онлайн** (зелёная) · **Оффлайн** (красная; 0 — «всё в норме»).

### 6.2 Карточка хоста
**Шапка:** статус-точка → **системный hostname** (жирный) → ping (мс) → кнопка терминала `›_`.
Строка тегов (цветные капсулы, клик = фильтр) — **скрывается, если тегов нет**.

**Паспорт:** 🖥 N Cores · ▭ RAM · 💽 тип диска + объём · ⏻ uptime · 🌡 температура.

**Живые метрики (4 блока):**
- **CPU %** / **RAM %** — кольцевые progress-rings с пороговой окраской (см. 6.3).
- **Сеть** — ↑/↓ + бейдж аплинка (100/1G/2.5G/10G…).
- **Диск I/O** — R/W + бейдж типа диска (nvme/ssd/hdd).

### 6.3 Пороговая окраска колец
| Состояние | Диапазон | Цвет |
|---|---|---|
| Норма | `< warning` | зелёный |
| Warning | `warning … critical` | оранжевый |
| Critical | `≥ critical` | красный |

### 6.4 Группы и теги
- **Группы** — секции с заголовком; хост без группы — секция «Прочее». При пустом списке групп
  карточки выводятся **плоско** (`HostGrid` без группировки).
- **Сворачивание** — клик по заголовку группы сворачивает её (chevron). Свёрнутая группа **прячет карточки и не опрашивается** (автопауза мониторинга); разворот возобновляет опрос с мгновенным обновлением. Свернутость реальных групп персистируется в YAML (`collapsed: true`).
- **Теги** — фильтры-капсулы; палитра фиксированная именованная, маппится в `SwiftUI.Color`.

### 6.5 Взаимодействие с карточкой
- **Правый клик** (context menu): назначить группу/тег, **создать новую** группу/тег (через алерт), **удалить хост** (подтверждение).
- **Drag-and-drop** карточки на другую карточку — перенос в группу целевой.
- **`›_`** — открыть `ssh <host>` в Terminal.app (`serveraliveinterval=30`).
- **Консоль** (иконка терминала в шапке): журнал действий и ошибок — сбой SSH, переходы online/offline, события конфига, действия пользователя; автоскролл, фильтр «Все/Ошибки», очистка, счётчик новых ошибок.

### 6.6 Тема
`theme: system|light|dark`; переключатель в UI с override в `UserDefaults` (приоритет над конфигом).
Вся спецификация на semantic-цветах — тёмная тема бесплатно.

## 7. Polling, отказоустойчивость, hot-reload

- Интервал `poll_interval` (дефолт 5с, per-host override); параллельность — `max_concurrent`.
- SSH через `Process` → `/usr/bin/ssh`, таймаут → `terminate()`; учитывает `~/.ssh/config` и `known_hosts`.
- Offline: N пропусков подряд → точка 🔴; восстановление — после первого успешного опроса.
- Дельта-счётчики: отрицательная дельта → 0 (защита от сброса хоста).
- Hot-reload: `DispatchSource.makeFileSystemObjectSource` на файл YAML → перечитывание → перерисовка;
  идентичность хостов по `name`.

## 8. Безопасность

- Приложение не хранит креды; авторизация — только ключи пользователя в `~/.ssh`.
- SSH-контур — только исходящие коннекты к хостам из конфига; манифестов не модифицирует.
- В публичном репо — только `config.example.yaml` со заглушками; реальные хосты в приватном,
  gitignored `config.yaml`.

---

## 9. Зависимости (итог)

- **Внешние:** нет (собственные `YamlMini`, `Check`).
- **Системные:** `/usr/bin/ssh`, `ping`, `top`, `df`, `vm_stat`, `netstat`, `iostat`, `lsblk`, `nproc`,
  `sensors`(если есть) и прочие стандартные утилиты ОС; SwiftUI/Foundation SDK.
- **Без** сторонних фреймворков и сетевых библиотек.
