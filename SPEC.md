# homelab-dashboard — спецификация устройства

Нативное macOS-приложение (Apple Silicon), дашборд мониторинга Linux/macOS-серверов по SSH.
Отображает живое состояние хостов: статус, паспорт (cores/RAM/диск/uptime/температура),
нагрузку (CPU/RAM/сеть/диск-I/O), разбивку на группы, цветные теги, светлый/тёмный режим.
Конфигурация — YAML, изменения применяются мгновенно (hot-reload) без перезапуска.

---

## 1. Цели и не-цели

**Цели**
- Мониторинг в реальном времени, без истории: только текущие живые значения.
- Минимум зависимостей: одна внешняя библиотека (Yams, парсер YAML), всё остальное — системные
  бинарники macOS (`/usr/bin/ssh`, `ping`) и SDK (SwiftUI, Foundation).
- Сборка/запуск строго под ARM (Apple Silicon).
- Авторизация на хостах переиспользует `~/.ssh/config`, `known_hosts` и ключи пользователя —
  приложение не хранит и не запрашивает пароли.

**Не-цели (осознанно исключено)**
- История метрик, спарклайны, графики за период.
- Уведомления (нотификации при offline/warning). «Нет уведомлений, только подсветка в UI».
- Управление хостами (deploy/exec/reboot), терминальный доступ.
- Сбор агента на целевых серверах — только pull по SSH.

## 2. Стек и платформа

| Слой | Выбор |
|---|---|
| Язык | Swift 6 |
| UI | SwiftUI (окно-дашборд, один основной window) |
| Сборка | Xcode project + Swift Package (ядро) |

## 3. Архитектура

```
┌────────────────────────────────────────────┐
│ SwiftUI view (window)                       │
│  - SummaryCard ×3, GroupSection, HostCard  │
│  - TagFilter, ThemeToggle                  │
└───────────────▲────────────────────────────┘
        данные / ObservableObject (DashboardModel)
┌───────────────┴────────────────────────────┐
│ PollingEngine                              │
│  - Timer (poll_interval) кажд. host        │
│  - параллельно (maxConcurrent)             │
│  - /usr/bin/ssh host 'batch-команды'       │
│  - дельта-счётчики (net/disk-I/O)          │
└───────────────▲────────────────────────────┘
        snapshot метрик
┌───────────────┴────────────────────────────┐
│ ConfigLoader                               │
│  - парсит YAML → Config (hosts/groups/tags)│
│  - DispatchSource FSEvents → hot-reload    │
└────────────────────────────────────────────┘
```

Поток данных односторонний: ConfigLoader → PollingEngine → DashboardModel → SwiftUI.
`DashboardModel` хранит последний валидный snapshot каждого хоста; при сбое SSH узел
переходит в «offline» после N пропусков, но прошлые метрики не стираются из вида.

## 4. Схема YAML-конфига

```yaml
poll_interval: 5          # сек, интервал опроса (Timer)
timeout: 5                # сек, таймаут ssh-сессии на хост
offline_after_misses: 2   # N неудачных опросов подряд → статус offline
max_concurrent: 4         # параллельных ssh-соединений
theme: system             # system | light | dark

thresholds:               # пороги окраски CPU/RAM колец (в %)
  warning: 60             #   зелёный → оранжевый
  critical: 85            #   оранжевый → красный

groups:                   # группы = секции-заголовки в UI (иерархия)
  - name: Кластер k8s
  - name: NAS / storage

tags:                     # цветные лейблы-фильтры
  - { name: prod, color: green }
  - { name: backup, color: blue }
  - { name: critical, color: red }

hosts:
  - name: k8s-01           # имя в UI (идентификатор для merge при reload)
    ssh: root@192.168.3.10 # адрес для system-ssh; хост/ключ/порт берутся из ~/.ssh/config
    os: linux              # linux | macos (выбор пачки команд); опц. autodetect
    group: Кластер k8s     # ссылка на group (необязательна — хост без группы отдельно)
    tags: [prod, critical] # цветные теги
    region: ru             # флаг локации (🇷🇺/🇩🇪/…), опционально
    metrics:               # по-хостовые вкл/выкл (источник «тонких» хост-ограничений)
      cores: true
      ram: true
      disk: true
      temp: true
      net: true
      iostat: true
```

Правила:
- `name` — стабильный идентификатор; при hot-reload состояние метрик хоста переиспользуется,
  если `name` совпал (нет «прыжка» карточек/сброса дельта-счётчиков).
- `os` необязателен: если пуст — автодетектой через `uname` при первом опросе.
- Недоступная метрика (например, `temp` на macOS без SMC) → `N/A`, карточка не падает.

## 5. Метрики и команды сбора

Единая нормализованная схема метрик; сбор — одной ssh-сессией пачкой команд (batch),
дельта-счётчики (сеть/диск-I/O) считаются разницей между последовательными опросами.

| Метрика | Linux (`os: linux`) | macOS (`os: macos`) | Примечание |
|---|---|---|---|
| Cores | `nproc --all` | `sysctl -n hw.ncpu` | статично |
| RAM total | `/proc/meminfo` MemTotal | `sysctl -n hw.memsize` | статично (можно кэшировать) |
| RAM used % | `/proc/meminfo` `(MemTotal−MemAvailable)/MemTotal` | `vm_stat` страницы used/(used+free) | живое |
| Disk total | `df -B1 --total` sum | `df -kl` sum | статично |
| Uptime | `/proc/uptime` (сек) | `sysctl kern.boottime` | сек → «Xd Yh» |
| Температура | `sensors -u` (CPU agg) | — недоступна по умолчанию → N/A | может отсутствовать и на Linux (нет lm-sensors/прав) → N/A |
| Net ↑/↓ | `/proc/net/dev` rx/tx дельта | `netstat -ib` rx/tx дельта | `B/s`→`K/s` формат |
| Disk I/O R/W | `/proc/diskstats` секторов×512 дельта | `iostat -d` (может требовать прав) → N/A | дельта |

Ping (задержка) — независимо от SSH, `ping -c3 / avg ms`, отображается 🟢 при живом хосте.

Формат вывода по SSH — строгий построчный `key=value`, парсится строго; неизвестная строка
игнорируется. Ненулевой код выхода/таймаут ssh = неуспешный опрос.

## 6. Спецификация UI

### 6.1 Сводные карточки (агрегаты, верх ряда)
- **Итого** — синяя точка + число хостов из конфига.
- **Онлайн** — зелёная точка + число живых.
- **Оффлайн** — красная точка + число offline (0 зеленит «всё в норме»).
Подпись сверху, большой жирный счётчик, цветная статус-точка.

### 6.2 Карточка хоста (сетка / колонки внутри группы)
**Шапка:** флаг региона → имя хоста (жирное) → статус-точка (🟢/🔴) → ping (мс, зелёный).
Строка тегов — цветные капсулы (клик = фильтр).

**Характеристики (паспорт):** 🖥 `N Cores` · ▭ RAM total · 💽 диск total · ⏻ uptime `Xd Yh` · 🌡 температура `°C`.

**Живые метрики (4 блока, тонкий разделитель сверху):**
- **CPU %** — кольцевой progress-ring: подложка-трек, сегмент-прогресс, % внутри.
- **RAM %** — тот же ring.
- **Сеть** — ↑ upload / ↓ download (число + `K/s`).
- **Диск I/O** — R / W (число + `B/s`/`K/s`).

### 6.3 Пороговая цветовая семантика (кольца CPU/RAM)
| Состояние | Диапазон | Цвет сегмента |
|---|---|---|
| Норма | `< warning` | зелёный (подложка голубая/нейтральная) |
| Warning | `warning … critical` | оранжевый |
| Critical | `≥ critical` | красный |

Пример из скрина: RAM 64% на k8s-02 → оранжевое кольцо (warning при пороге 60).

### 6.4 Группы и теги
- **Группы** — секции с заголовком (например «Кластер k8s», «NAS / storage»); внутри сетка карточек.
  Хост без `group` — секция «Прочее».
- **Теги** — цветные лейблы-капсулы на карточке; клик по тегу (в карточке или в панели фильтров)
  фильтрует видимые хосты. Палитра цветов фиксированная именованная
  (`green, blue, orange, red, purple, teal, gray…`), маппится в `SwiftUI.Color`.

### 6.5 Ночь/день
- `theme: system | light | dark` в конфиге; переключатель в UI (кнопка солнце/луна) с override,
  хранимым в `UserDefaults` (приоритет над конфигом). Применяется через
  `.preferredColorScheme` / `@Environment(\.colorScheme)` — вся спецификация на
  semantic-цветах (`Color.primary/.secondary`, ассеты набора light+dark), тёмная тема
  получается бесплатно.

## 7. Polling, отказоустойчивость, hot-reload

- **Интервал:** `poll_interval` (дефолт 5с) через `Timer`; параллельность ограничена
  `max_concurrent`.
- **SSH-запуск:** `Process` на `/usr/bin/ssh`, `timeout` → `terminate()`; учитывает
  `~/.ssh/config` (Host/User/Port/IdentityFile) и `known_hosts`. Никаких паролей.
- **Offline-детект:** N (`offline_after_misses`) неудачных опросов подряд → статус offline,
  точка 🔴, агрегат «Оффлайн» инкрементируется. Восстановление — после первого успешного.
- **Дельта-счётчики:** скорость сети/диск-I/O = (сейчас − предыдущий сэмпл) / интервал;
  обрыв счётчика (сброс хоста) защищён проверкой на отрицательную дельту → 0.
- **Hot-reload конфига:** `DispatchSource.makeFileSystemObjectSource` (флаги `.write/.delete`)
  на файл YAML → перечитывание → мгновенная перерисовка модели. Идентичность хостов по `name`
  сохраняет живые значения, теги/группы/пороги применяются сразу.

## 8. Безопасность

- Приложение не хранит креды/пароли; авторизация — ключи пользователя в `~/.ssh`.
- Работает только от читаемых полей конфига; `ssh_config`/`known_hosts` не модифицирует.
- Сетевой контур: только исходящие ssh/ping-коннекты к хостам из конфига.
- (Открытый репо) в `sample config.yaml` — только заглушки/локальные адреса, секретов нет.

---

## 9. Зависимости (итог)

- **Внешние:** `Yams` (парсинг YAML) — единственный.
- **Системные:** `/usr/bin/ssh`, `ping`, SwiftUI/Foundation SDK.
- **Без** Xcode-библиотек сторонних, без сетевых фреймворков (SSH не бандлится).
